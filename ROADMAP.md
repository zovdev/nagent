## 1. Принципы

1. **Сервер — единственный мозг, источник истины и стейт-машина.** aiohttp-сервер держит всю логику, состояние и настройки; фронт — «тупой болванчик»: каждый клик — запрос на сервер, сервер отвечает либо success (и стримит), либо fail с причиной (`locked by user 2`). `localStorage` не задействуется никогда.
2. **GUI-first, без TUI-припадков.** Никаких slash-команд: всё можно тыкать и щупать. macOS-эстетика: ничего лишнего не торчит, всё в модалках/вкладках. Клавиатура: TAB — переключение фокуса, Space — клик по сфокусированному, command palette — Ctrl+K (вин-клавиши в браузер не запихнёшь; на маке — Cmd+K).
3. **Максимум автоматизации по официальным спекам.** Всё, что можно вытянуть без юзера (`/models`, MCP discovery), подтягивается само.
4. **Данные — только из API. Никакой выдуманной хуйни.** Мы — агентная обвязка, не провайдер: провайдер = host + токен. Всё показываемое — выжато из его API: каталог — чистый passthrough `/v1/models` (контекст/флаги только если API явно заявил; не заявил — честное «неизвестно»; raw-JSON хранится и показывается целиком); токены/usage — только из `usage`-поля ответа (кеш-поля вербатим). Запрещены: локальные токенизаторы (tiktoken) и эвристики по имени модели, таблицы цен и расчёт стоимости, любые догадки там, где можно спросить API. Умная обвязка — да; выдуманные данные — нет.
5. **Тотальный контроль контекста.** Любое сообщение — от юзера или от AI — редактируется и удаляется из середины; ответ модели — на RAW-уровне (весь токен-стрим как текст).
6. **Прозрачность для юзера, минимализм для модели.** Юзер видит всю историю включая служебные обмены; модель видит только то, что нужно для работы.
7. **Три режима сервера:** соло / команда / аккаунты — одна кодовая база, три деплой-профиля.

## 2. Архитектура, API, режимы сервера

```
Browser SPA (render + input)
   ⇄ HTTP (клики/CRUD/настройки) + SSE EventSource (стрим ответов и событий)
aiohttp server-brain
   ├─ Agent Loop (генератор, turn pipeline, subagents, plan mode)
   ├─ History Store (append-only: SQLite + JSONL, tombstone/edit)
   ├─ Tool Registry + ToolSearch + Skills
   ├─ Permission Engine + Workspace Jail
   ├─ Provider Layer (OpenAI-compat, автопуллинг, fallback-каскад)
   ├─ MCP Client (auto-discovery)
   ├─ Web Tools (websearch / webfetch + глобальный кеш)
   ├─ Browser Engine (headless Chromium на сервере)
   ├─ Background Tasks (подсистема фоновых команд)
   ├─ Git Checkpoint Engine (shadow-git, diff-view)
   └─ Proxy Router (global / model_api / web / browser)
```

- **API-протокол (решено):** стрим ответов и все события сессии — **SSE (EventSource)**; все клики/CRUD/настройки — **обычный HTTP**. WebSocket — только для live-screencast браузера (фаза 4). EventSource легче для сервера и браузера, reconnect встроен.
- **Сеть:** bind `0.0.0.0` или `127.0.0.1` (настройка); CORS-allowlist — сервер открывается только с доверенных origin.
- **Админка:** первый вошедший после установки становится владельцем (admin) и проходит onboarding-настройку; после этого сервер уходит в заданный режим, но админка у владельца остаётся — отдельный адрес `/admin` с управлением сервером. Обычный интерфейс — на корне.
- **Хранение истории:** сервер хранит всё сам (append-only: edit/delete — события tombstone/replace; оригиналы остаются). UI подгружает историю чанками через API; при reconnect — `events?since=seq`, без клиентского стейта.
- **БД:** `main.db` — настройки сервера (binding, CORS, режим, прокси-матрица, websearch-кеш, провайдеры в соло/команде); `<user>.db` — чаты, настройки, skills, ключи юзера (режим аккаунтов). Миграции схемы — авто-апгрейд старых БД при обновлении версии.
- **Блокировки (shared-проекты):** сервер — стейт-машина правды: генерация/редактирование/удаление — эксклюзивные операции; клик фронтендом → сервер отвечает success (и стримит) или fail с причиной `locked by user N`. Соло-режим: один юзер, всё равно через сервер (единая логика).

| Режим | Auth | Провайдеры/ключи | Лимиты конкурентности | Изоляция |
|---|---|---|---|---|
| **Соло** | выключена | общие, `main.db` | не нужны | одна рабочая папка |
| **Команда** | токен-сессии | общие, `main.db` | нужны: конкурентные генерации/тулзы, очередь задач | shared-проекты |
| **Аккаунты** | логин + пароль | свои у каждого, в `<user>.db`, зашифрованы паролем | не нужны | папка юзера изолирована |

- **Shared-проекты (команда):** проект помечается как shared — у каждого члена команды он появляется с припиской «общий»; остальное — личные сессии; провайдеры глобальные.
- **Аудит тулкаллов** (кто/какая сессия/какая модель/какая тулза/когда) — опционально, **по умолчанию OFF**; это НЕ внутренний append-only лог (тот всегда пишется и лёгкий — он же источник истории правок).

## 3. Провайдеры, модели, устойчивость

- Юзер вводит host в любом виде — `host`, `host/v1`, `host/v1/` — нормализуем, храним базовый host; endpoints подставляются сами.
- **Автопуллинг каталога:** по подключении тянем `/v1/models` — чистый passthrough. Context window и capabilities (tools/vision/thinking/video/audio) — только там, где провайдер явно заявил (маппинг известных полей: `supported_parameters`, `architecture.input_modalities`); не заявил — «неизвестно», без эвристик по имени. Raw-JSON хранится целиком и раскрывается в UI. Оверрайд — только контекст-окно (для метра); кнопка refresh; фоновая пересинхронизация. Цен нет — мы не провайдер.
- **Health-панель:** статус провайдеров и MCP-серверов — вкладка в настройках, статус-бейджи (online / latency / error).
- **Смена модели mid-chat:** селектор провайдера/модели справа снизу — дефолт-фишка; история остаётся, следующие ходы идут новой моделью.
- **Нормализация reasoning:** `reasoning_content` (DeepSeek), `thinking`-блоки (Anthropic), `think`-теги (Qwen/OpenRouter) → единый `ThinkBlock`.
- **Параметры генерации per chat / per model:** temperature, top_p, max_tokens, reasoning effort/budget — панель в UI.
- **Fallback-каскад:** список резервных провайдеров/моделей не ограничен; при сбое перебор по порядку. Ретраи настраивает юзер: сколько попыток перед сдачей, сколько секунд ждать (фикс. или экспоненциально). Переключение внутри одного хода «липкое»: итерации хода не прыгают между моделями; новый ход снова начинается с основной.
- **Rate limits — две политики:** RPM (429) → ретрай с бэкоффом (уважая `Retry-After`); исчерпание токенов/квота/лимит времени → немедленный сигнал к следующему в fallback-каскаде.
- **Подсчёт токенов — только из API.** Локальных токенизаторов (tiktoken) и эвристик НЕТ — их показания врут, а моделей сотни. Факт — из `usage`-поля ответа (в конце генерации): prompt/completion/total + кеш-поля провайдера — вербатим, без дописывания total. Контекст-метр чата — по последнему реальному usage (его prompt_tokens = текущий размер контекста) vs окно из каталога; до первого хода — «нет данных». Сумма за сессию — агрегация реальных usage. Компакция (§11) — тоже по реальному usage.

## 4. MCP — ноль ручного ввода

- Юзер кидает ссылку → авто-discovery по официальному спеку: `initialize`, `tools/list`, `prompts/list`, `resources/list` — имя сервера, функции, описания, схемы. Карточка сервера в UI.
- **Имена тулзов — родные.** Модель видит `echo_time`, а не `mcp__server__echo_time`: префиксы жгут контекст. Роутинг вызова на сервер-владелец — внутри обвязки (реестр = роутер). Коллизия имён (два сервера / конфликт с кор-тулзой) — минимальный суффикс `_2`, только при реальной коллизии.
- MCP-тулзы — в общем Tool Registry, доступны через **ToolSearch** (§6): схемы не раздувают промпт (анти-паттерн tool saturation).
- MCP-тулзы проходят общий permission-pipeline.
- Дорожная карта: URL (streamable HTTP/SSE) → stdio → OAuth.

## 5. Agent Loop — сердце

- **Луп — генератор** (аналог `queryLoop`): наружу yield'ятся события, внутри — turn pipeline: сборка промпта → LLM → параллельный dispatch тулзов → результаты в историю → следующая итерация, пока модель не перестанет звать тулзы.
- **StepContext-фриз (Codex):** замороженный снапшот контекста на момент вызова тулзы.
- **Rollout JSONL (Codex):** сессия = файл; resume = replay, fork = новый файл.
- **Steering / inbox (OpenCode):** сообщение юзера во время генерации подаётся агенту на ближайшем шаге.
- **Прерывание:** ESC-стоп; сессия остаётся консистентной.
- **Лимит итераций лупа на turn** — настраивается.
- **Детектор повторов (sliding window):** совпадение текста ≥ 90% = стоп + варнинг юзеру с кнопкой «продолжить».
- **Детектор падений тулзов:** N раз ПОДРЯД инструмент падает → варнинг юзеру + подсказка модели в контекст.
- **Subagents (Task-тул):** суб-агент с нулевым контекстом; основной агент задаёт `system_prompt`, `prompt`, **allowlist тулзов**. Назад — только результат; прогресс виден в UI, в контекст главной не попадает.
- **Plan mode — отдельный процесс:** read-only исследование → план; **в основной контекст идёт только окончательный план**; кнопка «Одобрить и приступить» → чеклист-артефакт с прогрессом; план редактируется до одобрения.

**Промпт план-мода (шаблон):**

> Ты в режиме планирования (PLAN MODE). Задача — исследовать и составить исполняемый план, НЕ внося изменений.
> Правила: только чтение (read/glob/grep/websearch); любые изменения запрещены. Сначала собери факты — найди релевантные файлы, функции, зависимости, ограничения; не предполагай — проверяй. Если данных не хватает — собери конкретные вопросы юзеру в конец плана.
> Структура ответа: 1) Цель — одним абзацем. 2) Что уже есть — найденные файлы/модули с путями. 3) Шаги — нумерованный список; для каждого: что делаем, какие файлы затрагиваем, риски. 4) Проверка — как убедиться, что работает (тесты/критерии). 5) Открытые вопросы.
> Каждый шаг атомарный: один шаг = один осмысленный коммит. Не начинай выполнение — финал вывода и есть план.

## 6. ToolSearch, Skills, command palette

- Модели отдаётся ~15–20 кор-тулзов + мета-тулз **ToolSearch**: полный каталог — отдельным документом; модель ищет и догружает схемы по требованию.
- **Skills — тот же паттерн:** SkillSearch (названия + краткие описания) → подгрузка тела скила при выборе. SKILL.md-совместимый формат, юзер-БД.
- **Встроенные действия — только кнопки:** Compact и Clear.
- **Command palette (Ctrl+K / Cmd+K на маке):** spotlight-поиск по действиям, макросам, чатам, настройкам — финальная замена слеш-команд.
- **Макросы юзера:** кнопка/хоткей; макрос = имя + промпт-шаблон + опция «выполнить сразу / показать в вводе». Редактор и хоткеи — в настройках.

## 7. Права и безопасность

- **Режимы permission:** `allow all` / `ask before execution`; движок deny-first с правилами per-tool / per-pattern.
- **UX ask-модалки:** «разрешить один раз» / «разрешить всегда для этого паттерна» / «отклонить».
- **Workspace Jail — два слоя:** (1) path-jail — канонизация путей, симлинки, `..`-обходы, абсолютные пути — всё проверяется на резолвнутом пути; (2) **OS-изоляция (сильная):** выше рабочей папки не уйти, глубже — можно: Linux — Docker/bubblewrap с bind-mount только рабочей папки (снаружи буквально нечего), macOS — Seatbelt-профиль. Пишет только в workspace; от чтения снаружи защищает именно OS-слой; чтение — deny-list (`.env`, ключи, `~/.ssh`) + ask.
- **Bash-маппинг:** tree-sitter-bash разбор → prefix-правила (с юнит-тестами, паттерн Codex) → approval.
- **Prompt-injection — два режима:** `OFF` (по умолчанию) / `paranoid` — модель-цензор без контекста сессии, со своим system prompt, проверяет только входящие данные (websearch/webfetch/MCP/тулзы). Всегда: untrusted-fencing + структурный барьер (permission + jail).
- **Шифрование ключей:** соло — без; аккаунты — ключ производный от пароля юзера; команда — опционально мастер-пароль сервера.
- **Hooks — да:** события (PreToolUse / PostToolUse / UserPromptSubmit / Stop / Notification...), хук = команда с таймаутом, JSON на stdin; **GUI-редактор** в настройках. Сценарии: автоформат, секрет-скан, блок паттернов, нотификации.

## 8. Промпты и инструкции

- **System prompt — иерархия:** сервер-дефолт → юзер-дефолт → рабочая папка → чат. Редактор в UI на каждом уровне.
- **AGENTS.md:** авто-загрузка из рабочей папки; delta-инъекция при изменении. Дописывать агент может только с разрешения юзера.

## 9. Контекст-контроль: UI + мозг

- **Удалить / отредактировать любое сообщение** из середины. **Каскад: редактирование середины осознанное** — всё вокруг стоит как есть; потеря хвоста prompt-кеша принята. Форк — отдельная кнопка, в т.ч. из середины.
- **Удаление сообщения с файловыми изменениями → git-revert + merge-request** (§14). **Редактирование — только контекст.**
- **Undo-удаление без расинхрона:** тост живёт локально; **запрос на сервер отправляется только после истечения таймера** — отмена до истечения = сервер вообще не узнает об удалении. Никаких гонок «нажал отмену, а сервер уже удалил».
- **История правок сообщения:** индикатор у отредактированного; клик → компактный список версий (внутренний append-only лог — лёгкий, пишется всегда; ≠ опциональному аудиту).
- **RAW-режим:** сообщение видно полностью без распарсинга — весь токен-стрим (think и не-think) как текст, тулкаллы и их ответы — JSON. Редактируется всё.
- **Continue:** у последнего AI-сообщения всегда кнопка «продолжить генерацию»; assistant-prefill где поддерживается, иначе resend-директива.
- **Настройка «отправлять полный контекст с think-блоками»:** вкл/выкл на юзера и чат; при выкл — санация перед отправкой, в UI/логе остаются.
- **THINK-блоки в UI:** во время генерации открыты и стримятся; после завершения — схлопываются, клик — раскрыть.

## 10. Атачменты: картинки, видео, аудио, файлы

- **Атачменты — всё:** картинки, видео, аудио, файлы; хранение — workspace (папка вложений).
- **Квота атачментов — только в режиме аккаунтов** (настройка сервера); соло — без квот.
- **Картинки:** vision — как есть; без — VLM-суммаризация (модель юзера); не указана — `[изображение]`.
- **Видео — только моделям с нативной поддержкой; матрица:**

| Семейство | Видео | Как подавать |
|---|---|---|
| **Gemini** | нативно | mp4, mpeg, mov, avi, x-flv, mpg, webm; >20 МБ — Files API; ~45 мин; 1 FPS статик / agentic для длинных; до 10 на запрос |
| **Qwen-VL (2.5/3)** | нативно | `video_url`-контент (vLLM/sglang/DashScope), кадры через qwen-vl-utils |
| **Gemma 3 (4B/12B/27B)** | формально | SigLIP image+video, аудио нет; локальные OpenAI-compat сервера обычно принимают только картинки — locally режем кадры сами |
| **GPT-4o и большинство** | нет | ffmpeg-кадры как картинки + аудиодорожка → ASR |

- **Capability-флаг видео:** только из каталога API (маппинг модальностей) / ручной override; нет флага — безопасный дефолт кадры+ASR (без угадывания по имени).
- **Аудио:** нативно (Gemini) — как есть; иначе ASR-транскрипт.
- **Уведомления:** прогресс фоновых задач, нотиф о завершении; кастомные звуки mp3/mp4 (аудиодорожка) на события.

## 11. Компакция, суммаризация, деньги

- **Порог компакции — одно поле:** `80%` (процент окна) или `15000` (без `%` — токены). Подсчёт — по реальному usage из API (кумулятивно за ход; последняя итерация = текущий размер контекста) — без токенизаторов.
- **Auto-compact:** фоновая задача (в окне prompt-cache), дешёвой моделью; system, первые сообщения и последние N — как есть. `forgotten_event_ids` (OpenHands): модель видит компакт, UI — всю историю.
- **Гигиена промежуточных шагов:** выжимки поисков/дампов; восстановимо из серверного кеша (§12).
- **Двухшаговая суммаризация больших тулз-выводов:** прога видит большой ввод → основная модель пишет промпт для суммаризации → дешёвая модель суммаризирует → основная видит только суммаризацию. **Промежуточный запрос исключён из истории модели, но виден юзеру.**
- **Prompt caching по максимуму:** стабильный prefix, provider-абстракция (cache_control / auto). Гибкость редактирования важнее кеша — осознанно.
- **Routing на дешёвую модель** для служебного (компакция, суммаризация, цензор paranoid) — настройка юзера.

## 12. Websearch / Webfetch — глобальный кеш

- **Websearch:** глобален для сервера; кеш в `main.db`; аргумент `fresh` — мимо кеша. Приватность — не проблема: запросы безликие (без куки/браузер-агента), от имени сервера.
- **Webfetch:** страница кешируется полностью — raw + Markdown. Аргументы: `raw|md`, `offset`, `length`, `fresh`. Без `fresh` — всегда кеш; нет кеша — интернет.
- **Eviction:** LRU + размерный кап + TTL.
- **Поиск по своим сессиям:** keyword-полнотекст по своим чатам/контекстам (в команде — включая shared, где состоит); семантический — позже опционально.

## 13. Встроенный браузер + фоновые задачи

- **Браузер живёт в server-brain** (headless Chromium, Playwright/CDP): автономия не зависит от вкладок; закрыл вкладку — сессия живёт.
- **Правая рабочая зона UI (вкладки):** файловый виевер (дерево workspace, превью) · гит-виевер (diff, чекпоинты, коммит кликом) · терминал (лог баш-команд агента, живой вывод) · браузер-лайоут (screencast). Красивая организация — единая правая панель с табами, как Xcode.
- **Screencast по WS** (единственное место, где WS нужен): адаптивный fps; опциональный форвард ввода; режимы live / DOM-snapshot / по шагам.
- Контексты per-сессия; прокси браузера — строка матрицы; скачивания — в workspace.
- **Подсистема Background Tasks:** агент создаёт фоновую задачу (тул), проверяет статус (тул), может повесить себя в ожидание (тул wait) — по завершении задачи агенту возвращается результат выполнения и цикл продолжается. Для юзера — живой вывод в терминал-табе + нотиф по завершении.

## 14. Git-чекпоинты: UUID ↔ commit, diff, revert

- **Привязка сообщение ↔ коммит:** сервер вяжет UUID каждого хода агента к чекпоинт-коммиту shadow-git. Ход без файловых изменений — коммита нет.
- **Удаление сообщения с файловыми изменениями → revert + merge-request:** сервер готовит revert именно того коммита → юзеру — запрос на слияние со сравнением версий и подсветкой изменений → «апрувнуть» (применить) или «оставить файлы». Конфликт revert с поздними правками → разрешение по хункам.
- **Shadow-git:** `.agent/git`; `.git` юзера не трогаем.
- **Редактирование сообщения — только контекст:** две независимые оси — контекст (модель) и файлы (гит).
- **Diff-view:** каждое изменение файла агентом — диффом с подсветкой синтаксиса; коммит кликом; таймлайн чекпоинтов рядом с историей; «откат файлов к сообщению N».

## 15. Таймауты тулзов и «чистая история»

- **Таймауты** bash/webfetch/браузер — настраиваемые.
- **Timeout-протокол:** тулза вылетает с timeout-ошибкой → агенту в контекст идёт: «вызов не успел завершиться за N сек; если задача долгая — вызови тот же тулкалинг с параметром `timeout=N_seconds`».
- **Чистая история (транзакционная):** если модель вызвала **ровно тот же тулкалинг с параметром timeout** — предыдущий неудачный тулкалл + timeout-варнинг + промежуточные think-блоки **затираются из модели-контекста**, остаётся чистый тулкалинг как был изначально. Юзер видит всю историю (включая затёртое — в аудите/развёртке); модель — чистый незабитый контекст.
